# Passage evidence for analysis

Analysis contract `reading-api-sdk-v4-passage-evidence` lets the provider select supplied passage IDs instead of copying source quotations. The service resolves those IDs to verbatim text and stores the existing `{source_quote, target_quote}` evidence shape. Item and graph APIs keep that shape. This change does not switch the configured model, enable embeddings, or reanalyze stored items automatically.

The current source is presented once as ordered passages, bounded to the existing 100,000-character extracted-text limit. Each passage is at most 800 characters; splitting preserves punctuation and whitespace and favors sentence or line boundaries. The payload signals source truncation. Prior context remains limited to five sources and three passages per source. Current IDs use `current:N`; prior IDs use `prior:N:M`, with both indexes scoped to this one request. Summaries and annotations have no selectable evidence IDs.

The provider returns one structured result from one request. A relationship selects one current passage and one passage belonging to its named target. Unknown IDs, cross-target IDs, reversed references, missing evidence, and references outside the supplied source context are discarded. The final normalizer still checks the resolved quotations against the actual current source text and the supplied target excerpts. Existing custom analyzer callers can continue passing quotations through the legacy schema and normalizer; they cannot bypass exact quotation validation.

The quotation gate verifies provenance only. A correctly selected pair of passages can still have an overstated relationship label. Instructions require support for a specific claim, compatible scope for contradictions, and preservation of qualifications and chronology. Thematic compatibility alone is insufficient for `supports`; contextual links should use `related` or be omitted. Duplicated arguments are not independent corroboration. These are model judgments requiring evaluation, not deterministic truth checks.

For maintenance, preview stale analyses before a small reanalysis batch. The contract version change marks older analyses stale through the existing freshness diagnostics. Audit selected passages and relationship meaning together, including qualified statements, time-dependent updates, duplicates, and plausible but unsupported thematic connections. Retain graph retrieval as opt-in until answer-level tests justify broader use; give the answer model the graph explanations when testing how it interprets those labels.

Frozen model comparisons should call `prepareProviderAnalysisInput` and use that same payload for every candidate model. Parse responses with `ProviderReadingAnalysisSchema`, resolve references with `resolveProviderAnalysisOutput`, and apply `normalizeAnalysis` against the original frozen source context. Count proposed relationships, valid reference pairs, accepted model relationships, and human-reviewed semantic correctness separately. Reference validity alone does not measure the quality of a model or justify a model switch.
